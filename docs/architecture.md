# Архитектура

Проект остаётся статическим сайтом: проверенный каталог, код и стили собираются в самостоятельный HTML. Сайт работает с диска и на GitHub Pages без сетевой загрузки данных.

## Поток данных

```text
Нормализованные JSON
       ↓ loadDatabase + validateData при сборке
Самостоятельный index.html
       ↓ createCatalog при запуске
Неизменяемые записи и индексы
       ↓ domain: сезон, поиск, применимость советов
       ↓ application: модель списка или подробностей
       ↓ components: разметка
       ↓ views: события и взаимодействие с DOM
```

## Ответственность модулей

| Папка                              | Ответственность                                       |
| ---------------------------------- | ----------------------------------------------------- |
| `data/products/`, `data/variants/` | Постоянные продукты и их варианты                     |
| `data/seasons/`                    | Сезонные профили и редакционные пояснения             |
| `data/advice/`, `data/evidence/`   | Советы, условия применения и основания                |
| `data/taxonomy/`                   | Происхождения и категории                             |
| `data/migrations/`                 | Явное соответствие прежних идентификаторов            |
| `content/`                         | Русские надписи интерфейса                            |
| `src/domain/`                      | Каталог и чистые функции, не читающие DOM и хранилище |
| `src/application/`                 | Сборка моделей экранов из предметных данных           |
| `src/state/`                       | Состояние фильтров и его проверяемые изменения        |
| `src/components/`                  | Отображение готовых моделей и экранирование текста    |
| `src/views/`                       | События, формы, диалог и жизненный цикл экранов       |
| `src/services/`                    | Настройки браузера и часы                             |
| `src/config/`                      | Порядок отображения статусов и размеры групп          |
| `scripts/lib/`                     | Чтение, проверка и сборка исходных данных             |

`src/app.js` создаёт один каталог, настройки и экраны. Новый совет или алгоритм не должен добавлять условия в этот файл.

## Контракты

`createCatalog()` строит закрытые индексы один раз. Продукт имеет собственный ID и не зависит от имени или минимального номера варианта. Производные записи для поиска содержат подписи происхождения, категории и месяцы; они вычисляются, а не редактируются второй раз. Все публичные записи неизменяемы.

`resolveSeason()` возвращает оценку конкретного варианта и выбранного месяца вместе с основаниями. Текущий формат `legacy-monthly` сохраняет исходные календарные оценки. Точная фенология из них не выводится автоматически.

`resolveAdvice()` возвращает общие советы, подходящие условные советы и рекомендации, для которых не хватает контекста. Разрезанный и целый продукт, домашний и промышленный режимы не смешиваются. Подмена общих рекомендаций задаётся явным `adviceOverrides`; черновик не скрывает опубликованную версию.

`buildProductList()` готовит список и счётчики для обоих экранов. `buildProductDetails()` определяет порядок вариантов, их сезонные оценки и советы. Повтор определяется ID совета, не совпадением текста.

Компоненты получают готовые модели. `variant-details`, `advice-section`, `storage-instructions` и `season-chart` развиваются независимо. Для численных сроков хранения выводятся единицы, точка отсчёта, условия и отличие оценки качества от срока безопасности.

## Состояние и настройки

Оба экрана владеют своим `FilterState`. Форма отправляет изменения в состояние; отрисовка не считывает фильтры из DOM заново. Это основа для будущего URL-состояния без второй реализации фильтров.

`Preferences` хранит версию 3 избранного с постоянными ID продуктов. Старые `r…` мигрируют по таблице соответствия. Прежний ключ остаётся доступен для восстановления; неизвестные ID не удаляются. При недоступном хранилище сайт продолжает работать в памяти.

`selectRepresentative()` поддерживает явно выбранный вариант, возвращает причину выбора и сообщает о конфликте с фильтром. Интерфейс закрепления и сохранение такого предпочтения — отдельный следующий этап.

## Контроль качества

Сборка проверяет уникальность идентификаторов, связи, области доказательств, конфликтующие замены, статусы публикации, режимы и единицы хранения. Она обнаруживает структурные ошибки, но не доказывает научную достоверность текста.

Поведенческие тесты покрывают неизвестное состояние продукта, сортовые исключения, черновики, промышленные советы, сохранность избранного и стабильность ID при переименовании. Браузерные тесты проверяют поиск, фильтры, календарь, диалоги, мобильную ширину, миграцию избранного и автономный HTML.

Историческая проверка `scripts/verify-v6-migration.mjs` подтвердила точный перенос всех 217 исходных записей. Она не входит в обычные тесты, чтобы последующие подтверждённые исправления содержания не требовали менять исторический эталон.

Сборка не меняет даты исследований и не запрашивает внешние источники. Правила редактирования: [editing.md](editing.md). Границы текущего этапа: [refactor-v6.md](refactor-v6.md). План развития: [future-architecture.md](future-architecture.md).
