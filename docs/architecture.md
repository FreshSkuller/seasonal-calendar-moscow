# Архитектура

Проект — статический сайт без сервера и базы данных на хостинге. Исходники разделены на небольшие модули; сборка объединяет их в один HTML, который работает на GitHub Pages и при открытии с диска. В браузере нет внешних библиотек или загрузки файлов данных.

## Слои

| Папка             | Ответственность                                                   |
| ----------------- | ----------------------------------------------------------------- |
| `content/`        | Тексты интерфейса, отделённые от поведения                        |
| `data/`           | Сведения о товарах и источниках                                   |
| `src/config/`     | Группы стран, порядок статусов, размер групп карточек             |
| `src/domain/`     | Чистые функции поиска, географии, сортировки; без DOM и хранилища |
| `src/services/`   | Настройки браузера и московская дата                              |
| `src/components/` | Функции, возвращающие разметку отдельных элементов                |
| `src/views/`      | Классы экранов: состояние, события и перерисовка                  |
| `src/shared/`     | Экранирование текста, подстановка переменных, поиск DOM-элементов |
| `src/templates/`  | Каркас страницы и отдельные разделы                               |
| `src/styles/`     | CSS по назначению; порядок задаётся в `manifest.json`             |
| `scripts/`        | Загрузка и проверка данных, сборка, локальный сервер              |
| `tests/`          | Проверки данных и логики; `browser/` — пользовательские сценарии  |

`src/app.js` соединяет слои: получает базу, создаёт настройки, диалог и экраны, связывает избранное и тему. Новую предметную логику следует добавлять в `domain`, а разметку карточек — в `components`, не увеличивая файл запуска приложения.

## Классы и состояние

- `Preferences` хранит избранное и тему, уведомляет подписчиков об изменениях. Сохраняет прежние ключи localStorage, поэтому избранное пользователей продолжает работать. Ошибка доступа к хранилищу не мешает пользоваться сайтом.
- `CalendarView` управляет фильтрами таблицы, выбранным месяцем и переключением года.
- `TodayView` управляет поиском сегодняшних товаров, группами и раскрытием дополнительных карточек.
- `DetailsDialog` открывает подробности выбранного товара.

Экраны получают зависимости через конструктор. Компоненты разметки не обращаются к localStorage. Оба экрана используют общие функции фильтрации и один экземпляр `Preferences`. У экранов предусмотрен `destroy()` для удаления обработчиков при замене экрана.

## Сборка

1. `scripts/lib/load-data.cjs` читает JSON и объединяет товары, сортируя по постоянному ID.
2. `scripts/lib/validate-data.cjs` проверяет месяцы, статусы, уникальность ID и ссылки на источники.
3. `scripts/build.cjs` подставляет разделы шаблона и тексты, соединяет CSS по manifest, собирает JavaScript через esbuild.
4. База, стили и код встраиваются в `index.html`. Prettier форматирует результат.

Сборка не меняет данные, не обновляет даты исследования и не запрашивает внешние источники. Версии инструментов зафиксированы lock-файлом. Данные для вставки в HTML сериализуются безопасно, а пользовательские надписи экранируются в компонентах.

## Проверки

`calendar.test.cjs` проверяет целостность базы и соответствие опубликованного HTML исходникам. `domain.test.js` проверяет поиск, месяцы, фильтры, географию, дату, настройки и экранирование. Playwright проверяет реальные действия в браузере, включая автономное открытие файла.

При изменении поведения сначала добавьте проверку ожидаемого результата. При обычной правке надписи достаточно существующих проверок и просмотра страницы. Для изменения CSS проверьте телефонную ширину и открытый диалог.
