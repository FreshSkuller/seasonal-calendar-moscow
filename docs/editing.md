# Как редактировать календарь

## Надписи

Все обычные тексты интерфейса находятся в `content/ru.json`, сгруппированные по экрану и назначению. Меняйте значения справа от ключей. Названия ключей связывают тексты с кодом.

Сохраняйте вставки вроде `{total}`: код подставляет туда число. Шаблоны HTML используют `{{page.key}}`; неизвестный ключ останавливает сборку. Значки и названия сезонных статусов находятся отдельно в `data/statuses.json`.

## Товары

Выберите файл в `data/products/`:

| Файл                     | Содержимое               |
| ------------------------ | ------------------------ |
| `russia-vegetables.json` | Овощи России             |
| `russia-berries.json`    | Ягоды России             |
| `russia-fruits.json`     | Фрукты России            |
| `import-vegetables.json` | Импортные овощи          |
| `import-fruits.json`     | Импортные фрукты и ягоды |

Каждый объект описывает сочетание продукта и происхождения. При переименовании меняйте `name`, сохраняя `id`: по нему работает избранное. Старые названия и сортовые обозначения можно оставить в `aliases` для поиска.

| Поле             | Что писать                                                                                            |
| ---------------- | ----------------------------------------------------------------------------------------------------- |
| `id`             | Постоянный уникальный идентификатор, например `r216` для следующей новой записи, если он ещё свободен |
| `name`           | Привычное человеку название                                                                           |
| `origin`         | Страна или российский регион, например `Россия · Сочи`                                                |
| `category`       | Название существующей категории или новой группы товаров                                              |
| `months`         | Ровно 12 кодов, с января по декабрь                                                                   |
| `sources`        | Ключи календарных источников из `data/sources.json`                                                   |
| `note`           | Пояснение к срокам и особенностям продукта                                                            |
| `confidence`     | Уверенность и основание оценки                                                                        |
| `supply`         | Что известно о поставках, с необходимыми оговорками                                                   |
| `basis`          | Основание и пределы календарного вывода                                                               |
| `aliases`        | Необязательный массив альтернативных названий для поиска                                              |
| `variety`        | Необязательное пояснение сорта                                                                        |
| `selection`      | Необязательные признаки выбора в магазине                                                             |
| `ripening`       | Необязательные сведения о дозревании после покупки                                                    |
| `qualitySources` | Источники советов о выборе и дозревании; обязательны при наличии таких советов                        |

Для новой позиции скопируйте близкую существующую запись, задайте свободный ID и замените сведения. Не переносите месяцы автоматически: разные страны и сорта могут иметь разный сезон. Можно добавлять новые JSON-файлы с массивами товаров в `data/products/`: загрузчик подхватит их автоматически.

## Месяцы и источники

| Код | Значение                |
| --- | ----------------------- |
| `p` | Пик                     |
| `g` | Хороший сезон           |
| `b` | Пограничный сезон       |
| `h` | Хранение                |
| `t` | Теплица                 |
| `n` | Не сезон свежего урожая |
| `u` | Недостаточно сведений   |
| `a` | Круглый год             |

Например, третий элемент `months` относится к марту. Наличие товара в продаже не подтверждает пик вкуса. Подтверждённый конец сезона позволяет указать `n` за пределами установленного периода, но отсутствие данных само по себе не означает `n`. Проверяйте возможность хранения, теплиц и другого урожая.

В `data/sources.json` ключ и поле `id` источника должны совпадать. Сохраняйте URL, название, дату публикации, дату проверки, применимость (`scope`) и ограничения (`limit`). Советы о спелости ссылаются на источники отдельно через `qualitySources`.

`data/metadata.json` содержит дату проверки всей базы. Меняйте её после проверки сведений, а не после изменения оформления. Исторический отчёт `docs/review-2026-09-20.md` описывает исследование на ту дату; встречающееся там старое имя `data/calendar.json` теперь соответствует совокупности файлов `data/`.

## Происхождение и оформление

Российские происхождения начинаются с `Россия` и автоматически попадают в общий фильтр России. Для новой зарубежной страны укажите её группу в `src/config/geography.js`. Тест географии обнаружит страну без группы.

Карточка списка находится в `src/components/product-card.js`, содержимое диалога — в `product-details.js`. Общий значок статуса — `status-badge.js`. Новую надпись сначала добавьте в `content/ru.json`, затем используйте её в компоненте.

Для CSS выбирайте файл по назначению: `today.css` — сегодняшний список, `calendar.css` — таблица, `dialog.css` — подробности, `responsive.css` — общие адаптивные правила. Порядок файлов в `manifest.json` влияет на переопределение стилей.

## После изменений

```sh
npm run format
npm run build
npm test
```

Если изменилось поведение, также выполните `npm run test:browser`. Посмотрите страницу, проверьте `git diff` и включите в коммит обновлённый `index.html` вместе с исходниками.

## Объединённые карточки

`cardName` — явно заданное общее имя продукта; одинаковые значения объединяются на обоих экранах. `name`, `origin`, `variety` и `months` описывают конкретный вариант и не должны теряться при объединении. Не объединяйте календари помесячным максимумом: такой график не принадлежит ни одному происхождению.

После фильтрации страны, сорта и статуса выбирается подходящий вариант выбранного месяца. Его исходный `variantId` открывает подробности первым; остальные варианты всегда доступны ниже. Избранное относится к общему продукту и использует минимальный числовой ID; старые ID мигрируют автоматически.

Проверка 21 сентября и оставшиеся пробелы: `docs/season-review-2026-09-21.json`. Не устраняйте `u` механической заменой на `n` или `b`: неизвестное хранение и неизвестные даты урожая должны остаться явно неизвестными.
