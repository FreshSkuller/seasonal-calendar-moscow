# Рефакторинг каталога — версия 6

Внедрены постоянные идентификаторы 91 продукта, отдельные записи 217 вариантов, сезонные профили, 84 переиспользуемых совета и 301 запись оснований. Варианты сохраняют прежние ID `r…`, общие продукты имеют новые постоянные `product-…`. После миграции эти ID не вычисляются из названий или состава вариантов.

Каталог собирается из нормализованных данных. `createCatalog()` один раз строит индексы и возвращает неизменяемые записи. Редактируемой копии прежней базы в приложении нет.

Сезонные оценки перенесены без переосмысления: `legacy-monthly` явно обозначает исходную редакционную модель. Отдельные факты о сборе и хранении из старых кодов не выдумывались. Общие абзацы советов тоже не интерпретировались автоматически как точные инструкции для определённого состояния покупки.

Доменные функции выбирают вариант, сезон и применимые советы. Слой `application` готовит модели экранов. Компоненты подробностей разбиты на вариант, график, советы и условия хранения; повторные советы определяются по ID.

Фильтры имеют самостоятельное состояние. Избранное мигрирует в версию 3 по явному соответствию старых ID; прежние данные не удаляются. Категории и происхождения вынесены в справочники, добавление страны больше не требует изменения JavaScript.

Проверка миграции восстановила все 217 старых записей и сравнила контрольные суммы: тексты, календари, источники, сорта и дополнительные поля сохранены. Контрольные суммы являются историческим артефактом, а не запретом на дальнейшее улучшение содержания.

Следующие продуктовые изменения будут использовать подготовленную основу: выбор состояния покупки, закрепление варианта в интерфейсе, прямые ссылки, список покупок и сравнение вариантов. Эти пользовательские возможности не включены в рефакторинг. Нынешний runtime остаётся JavaScript; типы данных контролируются проверкой каталога и поведенческими тестами. Переход к TypeScript можно выполнить отдельно без повторной миграции контента.
